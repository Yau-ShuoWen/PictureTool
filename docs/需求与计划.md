# 需求与计划

## 讨论记录（2026-11-18）

用户的图片集中在 `F:\哏圖`。Windows 文件管理器中，图片和所属文件夹难以互相定位，难以盘点增减和重复文件，完整备份不方便，无法靠图片文字搜索，缩略图体验也欠佳。

用户希望重新设计一个方便整理的界面，核心为三个区域：图片、快捷方式、文件夹。以目录树为主。把文件夹拖到快捷方式区域创建“传送门”；把图片拖到传送门，目标是将图片移入对应文件夹。支持多选图片。拖动后先显示待移动数量，确认后才执行移动。传送门长期保存，随时可移除，之后也能重新添加。

整理历史借鉴 Git 的“某个节点”概念，记录一次整理中发生的文件改动。具体交互以后再讨论。当前只记录，不主动恢复；只移动，不主动删除。用户一般不改文件名，重复导入时应比较内容指纹，不能只看文件名。

完整快照应包含图片文件、修改历史、索引等全部信息，打成压缩包；未来可能有云端，也可能没有。OCR 识别简体中文、繁体中文和英文。

用户要求第一版实现，并在项目内留下聊天内容与计划历史，供后续对话接续。这里记录的是需求与决策摘要，不含逐字聊天转录。

## 第一版已实现

- 三栏桌面界面，目录树导航和当前文件夹图片网格。
- 多选、文件名筛选、缩略图按需读取。
- 文件夹拖入传送门区，传送门持久保存及移除。
- 图片拖入传送门后进入待移动清单，确认后移动；同名目标不覆盖。
- 移动记录，以及基于 SHA-256 的完全相同文件检查。

## 后续待定义与实现

1. 图片与文件夹的双向定位和大量文件下的性能优化，需要结合真实目录规模验证。
2. 导入流程、重复导入时的呈现方式和冲突决策。
3. OCR 索引、增量更新及简繁英混合搜索。
4. 包含文件、历史、索引的完整快照压缩包与恢复验证。
5. 整理节点的划分、展示和操作方式。遵循当前“不主动恢复、不主动删除”。
6. 进一步改善缩略图浏览和缓存。

## 实现约束

图片目录原文件由工具直接读取。应用设置和整理记录保存在 Electron 用户数据目录，暂不写入图片目录。文件移动前核对目标同名文件，不覆盖已有文件。重复检查只读取文件，不删除或修改文件。
